# Numeric parity cases for the RANGE family — the single source both probes read.
#
# `range-winforms` (a .NET console app driving the REAL System.Windows.Forms
# controls) and `kubuno-desktop-controls`'s `parity_range` example each replay every case
# below and write the same JSON shape. Declaring the cases here, once, is what
# stops the two probes from quietly drifting apart.
#
# Line format:
#
#     <id> | <kind> | <step> ; <step> ; ...
#
# `#` starts a comment; blank lines are ignored. A case with no steps exercises
# the freshly-constructed control's defaults.
#
# Kinds:   hscrollbar  vscrollbar  trackbar  numericupdown  domainupdown
#
# Steps are `name=value` (a property assignment) or a bare `name` (an action).
# A step that the toolkit rejects by throwing — and that the port rejects by
# returning `Err` — is recorded as status "err"; the case then continues, so one
# rejected assignment does not hide the state that follows it.
#
#   scrollbars     min= max= value= small= large=
#                  lineup linedown pageup pagedown first last
#                  (the actions are driven in WinForms by the reflected
#                   WM_HSCROLL/WM_VSCROLL the native scroll bar sends, i.e. by
#                   the toolkit's own scrolling arithmetic, not by re-assigning
#                   Value — so `last` measures the reachable ceiling for real)
#   trackbar       min= max= value= small= large= freq=
#   numericupdown  min= max= value= inc= dp= hex= sep=   up down
#   domainupdown   items=a,b,c  sel=  sorted=  wrap=     up down
#                  (`up` = UpButton, `down` = DownButton)

# ── ScrollBar: defaults, and the Maximum - LargeChange + 1 ceiling ────────────
sb-defaults              | hscrollbar |
sb-reach-default         | hscrollbar | last
sb-reach-large20         | hscrollbar | large=20; last
sb-reach-large50         | hscrollbar | large=50; last
sb-reach-large1          | hscrollbar | large=1; last
sb-reach-large0          | hscrollbar | large=0; last
sb-reach-large-eq-range  | hscrollbar | large=101; last
# A LargeChange of 0 makes the reachable ceiling `Maximum - 0 + 1`, i.e. one
# HIGHER than Maximum itself. These three start from a known Value so that "did
# not move" can be told apart from "moved back to the floor".
#
# What they caught: the toolkit is internally inconsistent here. `DoScroll`
# computes 101 for the `last` gesture and then its own `Value` setter REFUSES
# it, so the case is recorded as `err` and the Value never moves. (That throw
# comes from inside `ScrollBar.WndProc`, which is why the probe must set
# `UnhandledExceptionMode.ThrowException` — otherwise WinForms swallows it into
# a modal dialog and the run hangs instead of recording anything.) Refusing is
# therefore the behaviour to reproduce; handing back 101 — a Value that the
# port's own `set_value` would reject — is not.
sb-large0-from50-last    | hscrollbar | large=0; value=50; last
sb-large0-from50-line    | hscrollbar | large=0; value=50; linedown
sb-large0-from50-page    | hscrollbar | large=0; value=50; pagedown
sb-reach-large-gt-range  | hscrollbar | large=500; last
sb-large-gt-range-read   | hscrollbar | large=500
sb-large-negative        | hscrollbar | large=-5
sb-small-negative        | hscrollbar | small=-1
sb-small-gt-large        | hscrollbar | small=25
sb-small-gt-large-step   | hscrollbar | small=25; linedown
